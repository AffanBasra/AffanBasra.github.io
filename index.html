NFL and NBA stats pipelines for StatRankings and DFS Army

Problem
Two US sports data companies needed fresh NFL and NBA stats in their databases on a fixed schedule, with no bad rows reaching their sites.
What I built
ETL pipelines in Python (Polars) loading into PostgreSQL on AWS RDS, on daily and weekly schedules. Schema checks on every load (NOT NULL, type, unique and CHECK constraints), so bad loads failed before reaching client tables, plus Slack and email failure alerts. I ran DFS Army's production database (tables, indexes, backups, monitoring) and worked directly with both clients.
Hard part
A wrong stat showed up on a client site. I traced it from the front end back to undocumented empty fields in a source API, and rebuilt the stat from a second API.

PipelineGuard: finds personal data before it enters a pipeline

Problem
Pipelines often copy personal data such as ID numbers, phones, IBANs and emails into places it should never be.
What I built
A Kafka stream processor with two layers: rules for CNIC, IBAN (mod-97 check), phone and email, then a GLiNER encoder for names and addresses. A PostgreSQL audit trail stores the entity type, span and confidence, never the value. Delivery is at-least-once with idempotent writes: no loss or duplication across a 2,500-message crash-and-replay test.
Results
96.0% address coverage on 2,786 real OpenStreetMap addresses after comparing 4 encoder models. Model memory cut from 1,780 MB to 845 MB with bf16 at unchanged coverage. 509 tests run in GitHub Actions.
1,267 records/safter micro-batching, about 180x faster

A safe Postgres migration and query tuning

Migration
Moved a startup's production database from Supabase to Neon (PostgreSQL 17) with pg_dump and pg_restore. Cleaned stale data first, verified all 11 tables by row counts and checksums, and cut over at night with a brief write pause. No data lost, rollback in about 2 minutes.
Query tuning
On my own 4M-row demo database, I traced slow dashboard queries with EXPLAIN ANALYZE and fixed them with a covering index and rewrites. Every fix returned identical results.
